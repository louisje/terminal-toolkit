# Working memory

Use `memory://scratchpad.md` with read, write and edit as a lightweight external working memory, not a second project management system.

- When work becomes complex, record the goal, a short nested TODO list, current focus and next action.
- Keep only useful facts, decisions, unresolved questions and concise reasoning summaries. Distinguish evidence from hypotheses.
- When temporarily investigating a side issue, preserve the parent focus so you can return to it.
- Revisit the scratchpad when resuming work, changing direction, or losing context. Update it at meaningful checkpoints, not every tool call.
- Revise or discard stale information; compress resolved investigations into conclusions. Keep it short enough to read in one call.
- The format is flexible Markdown. Do not duplicate durable project documentation; transfer durable decisions to the appropriate project files.
- If the scratchpad is missing, create it when useful. If conversation identity is unavailable, continue without it; never use a shared file as an automatic fallback.
- Memory is temporary and may expire or disappear on restart. Do not store credentials or rely on it for durable handoff.
